Bugs / Production Risks

  1. buildAvailableTime returns zero-time when endsAt == nil, but output still serializes it

  start_telemed_session_use_case.go:85-92 — When endsAt is nil, the method returns time.Time{} for both availableFrom and availableTo. The caller then passes these zero values to
  NewStartTelemedSessionNotEnabledOutput, which converts them to JST RFC3339 strings like "0001-01-01T09:00:00+09:00". This is likely confusing for the frontend. Consider
  returning nil for AvailableFrom/AvailableTo when endsAt is nil.

  2. TelemedSessionKey is optional:"true" — empty key silently produces valid-looking tokens

  env.go:61 — If TELEMED_SESSION_KEY is not set, the key defaults to "". sha256.Sum256([]byte("")) still produces a 32-byte key, so encryption will succeed silently but produce
  tokens that are incompatible with the PHP side. This should either be required, or the use case should fail fast if the key is empty.

  3. base64url encoding is done manually instead of using base64.RawURLEncoding

  private.go:72-76 — The manual strings.ReplaceAll("+", "-") / ReplaceAll("/", "_") / TrimRight("=") approach is functionally identical to base64.RawURLEncoding.EncodeToString().
  The existing codebase (auth/token.go:144) already uses base64.RawURLEncoding. Recommend using the stdlib for consistency and to avoid subtle encoding edge cases.
