  Bug: AvailablePlans serializes as null vs [] depending on path

  File: apps/apotool/internal/contract/usecase/smsusecase/fetch_sms_contract_status_use_case.go:84-93

  The early return for !termConsented creates a partial output struct:

  return &smsoutput.FetchSmsContractStatusOutput{

      Preconditions: smsoutput.PreconditionsOutput{
          TermConsented: termConsented,
      },
  }, nil

  Here AvailablePlans is a nil []PlanOutput, which serializes as "availablePlans": null in JSON.

  But in the normal path, availablePlans() at line 196 returns []PlanOutput{}, which serializes as "availablePlans": [].

  This inconsistency can break frontend code that does .length or iterates without a null check. The medicalboxair use case avoids this by not having an early return — it always goes through the domain object.

  Fix: Either initialize AvailablePlans: []smsoutput.PlanOutput{} in the early return, or remove the early return and always go through smsContract.toFetchSmsContractStatusOutput() (matching the medicalBoxAir pattern).
