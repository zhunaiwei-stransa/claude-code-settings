
## F2: regi_cards JOINの条件差異

### 問題

PHP側の `NOT => [brand => null, confirmed_at => null]` は CakePHP 2.x では `NOT (brand IS NULL AND confirmed_at IS NULL)` となり、De Morgan の法則で `brand IS NOT NULL OR confirmed_at IS NOT NULL` と等価。

Go側は `brand IS NOT NULL AND confirmed_at IS NOT NULL` であり、より厳密。

### 修正提案

Go側の方が正しいと考えるが、PHP との一貫性が必要な場合は以下のように修正：

**Go:** `apps/apotool/internal/pkg/infrastructure/rdb/persistence/regi_sbps_config_repository_impl.go:113-114`

```go
// 現在（厳密）
" AND rc.is_main_card = 1 AND rc.brand IS NOT NULL AND rc.confirmed_at IS NOT NULL",

// PHPと合わせる場合
" AND rc.is_main_card = 1 AND NOT (rc.brand IS NULL AND rc.confirmed_at IS NULL)",
```

**PHP:** `app/Model/RegiSbpsSettlement.php:500-512`

```php
// 支払患者のクレカ
[
    'type' => 'LEFT',
    'table' => 'regi_cards',
    'alias' => 'RegiCard',
    'conditions' => [
        'Patient.office_id=RegiCard.office_id',
        'Patient.payment_patient_id=RegiCard.patient_id',
        'RegiCard.is_main_card' => 1,
        'NOT' => [
            'RegiCard.brand' => null,
            'RegiCard.confirmed_at' => null,
        ],
    ]
],
```
